# Music Tagger 初始化页 PRD

## 1. 文档定位

本文档描述 `/setup` 的现状单页 PRD。该页只服务“创建首个管理员账号”这一件事，不扩展为公开注册页。

## 2. 产品背景

系统支持首次初始化管理员。初始化完成后，入口应立即关闭，并引导用户前往 `/sign-in` 继续后续流程。

## 3. 产品目标

- 让尚未初始化的系统能够创建首个管理员。
- 避免重复初始化。
- 在初始化完成或正在初始化时，给出清晰的后续去向。

## 4. 用户与权限

- 目标用户：部署后的首位操作者。
- 权限边界：仅在系统未完成初始化时可作为有效入口。
- 初始化后：页面不再提供可继续创建管理员的主表单。

## 5. 页面定位

这是一个一次性公共入口页，不是长期可用的注册中心。

- 核心任务：创建首个管理员。
- 结束语义：创建成功后关闭入口并跳转登录。

## 6. 页面结构

- 页面主体：居中单卡片。
- 卡片头部：标题、状态 Badge、引导说明。
- 卡片内容：
  - 未初始化时显示表单
  - 初始化完成或已初始化时显示完成态提示
  - 加锁中时显示等待说明
- 表单字段：昵称、邮箱、密码。

## 7. 页面字段定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 昵称 | string | 否 | 可选管理员显示名 |
| 邮箱 | string | 是 | 首个管理员登录邮箱 |
| 密码 | string | 是 | 至少 8 位 |
| 初始化状态 | enum | 是 | `loading / none / locking / initialized / unknown` |

## 8. 关键交互

1. 页面先读取 `setup.status` 判断当前系统状态。
2. 未初始化时，用户填写表单并提交创建管理员。
3. 创建成功后显示“初始化完成”提示，并延迟跳转到 `/sign-in`，同时携带邮箱预填。
4. 若页面刷新时发现系统已初始化，则直接显示“入口已关闭”，随后跳转登录页。
5. 若系统处于 `locking`，则阻止重复提交，并引导稍后刷新或直接去登录。

## 9. 页面状态

- 未初始化：展示完整表单。
- 初始化中：显示“初始化中”状态 Badge，并禁止创建动作。
- 已完成：展示完成态提示卡片和登录链接。
- 校验失败：邮箱为空或密码不足 8 位时直接提示错误。
- 接口失败：toast 提示初始化失败。

## 10. 原型与 UI 设计指导

- 保持单卡片、强聚焦布局。
- 状态 Badge 要可见，因为该页最重要的是“当前还能不能初始化”。
- 完成态应明显区别于表单态，避免用户误解为仍可继续创建账号。
- 登录跳转链接必须保留为明确退路。

## 11. 给 LLM 的输出约束

- 不要把本页做成普通用户注册页。
- 不要增加多管理员邀请、邮箱验证、角色选择等流程。
- 页面表达必须围绕“首次管理员初始化”展开。

## 12. 事实依据

- 页面读取 `setup.status` 并根据 `initialized / locking` 渲染不同状态。
- 创建成功后会自动跳转到 `/sign-in`，并带上邮箱 query。
- 当前代码明确说明“初始化已完成，入口已关闭”。
