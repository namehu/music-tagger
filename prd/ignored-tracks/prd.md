# Music Tagger 我的忽略页 PRD

## 1. 文档定位

本文档描述 `/ignored-tracks` 的单文件 PRD。页面只服务用户本人管理“我的忽略”列表，不承担全局忽略管理。

## 2. 产品背景

当前系统支持双层忽略规则：用户级“我的忽略”和管理员级“全局忽略”。本页用于让用户回看并撤销自己主动隐藏的曲目。

## 3. 产品目标

- 让用户看见自己隐藏过哪些曲目。
- 支持把单首曲目恢复回默认曲库。
- 补齐用户侧忽略规则的可回收入口。

## 4. 用户与权限

- 目标用户：已登录用户。
- 权限边界：只能查看和解除自己的忽略。
- 非目标：不能在这里操作全局忽略。

## 5. 页面定位

这是一个“个人忽略回收页”。

- 页面主任务：查看已忽略曲目并解除。
- 与 `/library` 的关系：用户通常在曲库里发起忽略，在这里回收。

## 6. 页面结构

- 页面标题区：标题与过滤影响说明。
- 单张列表卡片：
  - 标题、艺人、专辑、路径
  - 忽略时间
  - 解除忽略按钮

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 曲目标题 / 艺人 / 专辑 | string | 以当前显示摘要为准 |
| 曲目路径 | string | 文件真实路径展示 |
| 忽略时间 | datetime | 用户创建忽略记录的时间 |
| trackId | string | 解除忽略动作的目标 |

## 8. 关键交互

1. 页面读取 `ignoredTracks.listMine`。
2. 用户点击“解除忽略”后，调用 `unignoreMine`。
3. 成功后刷新当前页，并同步刷新曲库列表与统计。

## 9. 页面状态

- 正常态：表格展示已忽略曲目。
- 空态：提示“你还没有忽略任何曲目”。
- 提交中：解除按钮禁用。
- 失败态：toast 提示解除忽略失败。

## 10. 原型与 UI 设计指导

- 保持表格化展示，突出“这首歌何时被隐藏、现在能否恢复”。
- 路径信息应保留，但作为次级信息处理。
- 页面视觉重点应放在可恢复性，而不是复杂筛选。

## 11. 给 LLM 的输出约束

- 不要加入批量操作、全局忽略管理或高级规则编辑。
- 不要在本页展示正常曲库内容。
- 保持页面功能单一：列出并解除我的忽略。

## 12. 事实依据

- 页面当前只调用 `ignoredTracks.listMine` 与 `unignoreMine`。
- 解除成功后会刷新曲库列表和统计。
- 页面文案明确说明这些曲目会从默认曲库、搜索结果和歌单候选中隐藏。
