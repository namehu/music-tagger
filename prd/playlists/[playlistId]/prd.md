# Music Tagger 歌单详情页 PRD

## 1. 文档定位

本文档描述 `/playlists/[playlistId]` 的当前页面边界。它是单个个人歌单的播放与加歌页面，不扩展为拖拽排序或高级队列编排器。

## 2. 产品背景

当前系统已支持按歌单保存顺序点播，并允许从曲库搜索候选曲目加入歌单。歌单详情页是歌单消费和维护的唯一详情入口。

## 3. 产品目标

- 让用户按歌单保存顺序播放曲目。
- 支持把搜索到的曲目加入当前歌单。
- 在详情页明确歌单与当前播放队列的关系。

## 4. 用户与权限

- 目标用户：该歌单所属用户。
- 权限边界：仅提供个人歌单的播放与维护动作。
- 忽略规则：歌单内保留已忽略曲目展示，但候选加歌列表会过滤忽略曲目。

## 5. 页面定位

这是一个“双栏详情页”。

- 左侧：当前歌单曲目及顺序播放。
- 右侧：从曲库搜索后单首加入。

## 6. 页面结构

- 顶部标题区：歌单名、播放模式、当前队列来源、恢复状态。
- 左列歌单区：
  - 曲目表格
  - 播放按钮
  - 忽略来源标记
  - 移除曲目 / 解除我的忽略
- 右列加歌区：
  - 搜索框
  - 过滤说明
  - 候选曲目列表
  - 单首加入按钮

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| playlistId | route param | 当前歌单标识 |
| 歌单曲目 items | array | 包含曲目摘要、顺序、忽略来源 |
| 搜索词 | string | 用于查找加歌候选 |
| playbackMode | enum | 当前用户播放模式摘要 |
| queueSourceKey | string | 当前用户队列是否来自此歌单 |

## 8. 关键交互

1. 页面根据 `playlistId` 读取歌单详情。
2. 首次拿到歌单曲目后，把歌单顺序同步到用户播放队列。
3. 点击歌单内任意曲目时，如当前队列不是本歌单来源，会先用歌单顺序重建队列再播。
4. 用户可从歌单中移除某首曲目。
5. 右侧搜索候选曲目后，可单首加入当前歌单。
6. 若歌单内曲目带有“我的忽略”标记，可在此页直接解除。

## 9. 页面状态

- 加载中：歌单表格或候选区显示加载提示。
- 正常态：显示双栏布局。
- 空歌单：左侧提示当前歌单还没有曲目。
- 候选空态：搜索无结果或当前没有可加入候选。
- 播放准备态：当前行显示“准备中”。

## 10. 原型与 UI 设计指导

- 双栏布局要清晰区分“播放现有内容”和“继续加歌”。
- 左列应突出顺序关系，因此保留序号列。
- 队列来源和播放模式应以轻量状态标签显示。
- 右侧说明中明确当前版本不做拖拽排序。

## 11. 给 LLM 的输出约束

- 不要增加拖拽排序、批量加歌、分享、协作或公开链接。
- 不要把右侧候选区改成复杂筛选面板。
- 保持当前闭环为“按现有顺序播放 + 搜索后单首加入”。

## 12. 事实依据

- 页面通过 `useParams()` 获取 `playlistId`。
- 歌单详情页会把 `playlist:${playlistId}` 作为用户队列来源。
- 当前版本明确说明“先支持搜索后单首加入，不做拖拽排序”。
