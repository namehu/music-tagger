# Music Tagger 应用根路由 PRD

## 1. 文档定位

本文档描述 `/` 根路由在当前 Web 系统中的真实职责。它不是内容页，也不承担登录判断后的复杂分流逻辑，而是一个极轻量的路由分发页。

## 2. 产品背景

当前系统已把登录后的默认入口收敛到用户区 `/dashboard`。因此应用根路由只负责把进入 `(app)` 壳的访问统一导向默认已登录首页，避免出现第二套首页定义。

## 3. 产品目标

- 为已进入应用壳的访问提供唯一默认落点。
- 避免在根路由重复建设一个与 `/dashboard` 并行的首页。
- 为原型、UI 和代码生成明确说明该页不承载业务内容。

## 4. 用户与权限

- 目标用户：已进入应用壳的登录用户。
- 权限边界：本页不直接展示权限相关 UI，也不做管理员专属分流。
- 默认去向：`/dashboard`。

## 5. 页面定位

这是一个“跳转页”，不是“展示页”。

- 页面职责：收到访问后立即跳转到默认已登录路径。
- 页面价值：统一入口、减少重复导航判断。

## 6. 页面结构

- 无可见业务内容。
- 无表单、列表、卡片或摘要区块。
- 实现形态为同步 `redirect()`，不保留过渡布局。

## 7. 页面字段定义

本页无用户可见字段。

## 8. 关键交互

1. 用户访问 `/`。
2. 系统立即跳转到 `/dashboard`。
3. 页面本身不展示任何中间确认、按钮或提示文案。

## 9. 页面状态

- 正常态：立即跳转到 `/dashboard`。
- 异常态：当前代码未提供单独异常 UI，本页不承担错误恢复能力。

## 10. 原型与 UI 设计指导

- 不要把本页设计成真正首页。
- 不要添加欢迎语、统计卡、快捷入口或任何与 `/dashboard` 重复的模块。
- 如下游原型工具必须画出节点，可用“透明跳转节点”或“无 UI 页面”表示。

## 11. 给 LLM 的输出约束

- 不要为 `/` 发明新的信息架构。
- 不要添加登录判断、管理员分流或品牌宣传区块。
- 保持实现目标单一：进入后跳转到 `/dashboard`。

## 12. 事实依据

- 根路由页面只调用 `redirect(DEFAULT_SIGNED_IN_PATH)`。
- `DEFAULT_SIGNED_IN_PATH` 当前固定为 `/dashboard`。
- 当前系统的真实用户首页是 `/dashboard`，而不是 `/`。
