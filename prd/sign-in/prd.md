# Music Tagger 登录页 PRD

## 1. 文档定位

本文档描述 `/sign-in` 的当前真实形态，用于支持原型、UI 和示例代码生成。它是一个标准登录入口，不扩展为注册、找回密码或多身份切换中心。

## 2. 产品背景

当前系统基于 better-auth 提供登录能力。登录成功后默认进入用户音乐区 `/dashboard`；如用户是从受保护页面跳来，会优先返回 `next` 指定路径。

## 3. 产品目标

- 提供最小、稳定的邮箱密码登录入口。
- 支持登录后继续访问原目标页面。
- 为尚未初始化的系统保留去 `/setup` 的引导。

## 4. 用户与权限

- 目标用户：系统已存在账号的用户与管理员。
- 权限边界：本页不区分角色表单；角色差异发生在登录后页面访问边界。
- 公共访问：未登录用户可直接访问。

## 5. 页面定位

这是一个公共单页表单，不是营销首页，也不是完整账号中心。

- 核心任务：输入邮箱和密码并完成登录。
- 次要任务：提示未初始化系统可以去 `/setup`。

## 6. 页面结构

- 页面主体：居中的单张登录卡片。
- 卡片头部：标题“登录”与说明文案。
- 卡片内容：邮箱输入框、密码输入框、提交按钮。
- 卡片底部：跳转到 `/setup` 的辅助链接。

## 7. 页面字段定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 邮箱 | string | 是 | 支持从 query `email` 预填 |
| 密码 | string | 是 | 当前密码输入框，不提供显隐切换 |
| next | query string | 否 | 登录成功后回跳目标；为空时回 `/dashboard` |

## 8. 关键交互

1. 页面加载时读取 query 中的 `email` 与 `next`。
2. 用户提交邮箱和密码后，调用邮箱密码登录。
3. 登录成功后，优先跳转到 `next`，否则跳转到 `/dashboard`。
4. 登录失败时，保留输入内容并弹出错误提示。
5. 用户可通过底部链接跳转到 `/setup`。

## 9. 页面状态

- 初始态：显示空表单或带预填邮箱的表单。
- 提交中：按钮进入 `登录中...` 状态并禁用重复提交。
- 失败态：toast 提示登录失败或后端返回的错误信息。
- Suspense 回退态：显示同结构的轻量加载卡片。

## 10. 原型与 UI 设计指导

- 使用单列、低干扰、居中卡片布局。
- 主视觉重点放在表单可读性，不要堆叠多余说明。
- `next` 存在时，应把“登录后继续访问”作为说明文案主语义。
- `/setup` 链接应弱于登录按钮，但保持可见。

## 11. 给 LLM 的输出约束

- 不要新增注册、验证码、找回密码、第三方登录。
- 不要把页面扩写成品牌首页或账号管理中心。
- 保持交互闭环为“输入邮箱密码 -> 登录 -> 回跳目标页或 `/dashboard`”。

## 12. 事实依据

- 当前页面通过 `signIn.email` 完成登录。
- 回跳路径由 `resolveSignInCallbackPath(next)` 解析，默认值为 `/dashboard`。
- 页面底部明确保留“还未初始化？去初始化”的链接。
