# Music Tagger 管理音乐库页 PRD

## 1. 文档定位

本文档描述 `/admin/library` 的当前单文件 PRD。它是管理员的曲库浏览与单曲编辑入口，不再以 Plan 方式承担日常元数据编辑。

## 2. 产品背景

当前系统已将管理员单曲编辑主线收敛为“先写数据库，再异步回写源文件”。因此管理音乐库页的重点是搜索曲目、试听、打开编辑抽屉、设为全局忽略。

## 3. 产品目标

- 提供管理员可用的曲库总览与搜索入口。
- 支持单曲级元数据、歌词、封面编辑。
- 提供全局忽略和管理试听能力。

## 4. 用户与权限

- 目标用户：管理员。
- 权限边界：普通用户不可使用本页的编辑与全局忽略动作。
- 播放会话：绑定 `admin` 临时试听会话。

## 5. 页面定位

这是一个“管理曲库列表页”。

- 主列表负责搜索、排序、试听和全局忽略。
- 编辑抽屉负责单曲元数据、歌词、封面编辑与同步状态查看。

## 6. 页面结构

- 页面标题区：标题与单曲编辑说明。
- 统计卡区：曲目、专辑、艺人数。
- 列表控制区：搜索、排序、已编辑筛选、队列状态标签。
- 曲目表格：
  - 播放
  - 编辑
  - 全局忽略
  - 标题、艺人、专辑、路径、更新时间
- 右侧抽屉：
  - 元数据编辑
  - 歌词编辑
  - 封面上传/移除
  - 每个编辑域的同步状态与 Jobs 跳转

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 搜索词 | string | 按标题、艺人、专辑、文件名或路径搜索 |
| 排序 | enum | `recent / title / artist` |
| 已编辑筛选 | enum | `all / edited / unedited` |
| 曲目行编辑摘要 | object | 是否存在 metadata / lyrics / cover edit |
| 编辑抽屉字段 | object | 元数据、歌词、封面当前真值与扫描回退值 |

## 8. 关键交互

1. 管理员搜索与排序曲目列表。
2. 点击播放后，当前可见列表成为 `admin` 试听队列来源。
3. 点击“编辑”打开单曲编辑抽屉。
4. 在抽屉中保存元数据、歌词或封面后，数据库值立即生效，再由后台异步写回音频文件。
5. 如同步失败，可在抽屉中重试同步或跳转 `/admin/jobs` 查看详情。
6. 管理员可对某首歌执行“全局忽略”。

## 9. 页面状态

- 列表加载中 / 搜索中。
- 编辑抽屉加载中。
- 同步状态：`pending / syncing / synced / failed`。
- 无结果空态：列表无匹配曲目时显示空提示。

## 10. 原型与 UI 设计指导

- 页面仍以“列表管理”为主，编辑应使用抽屉而不是跳转独立详情页。
- 抽屉中应强调“保存即生效，后台继续写回文件”的语义。
- 同步状态面板要清晰、结构化，优先展示可操作建议。
- 不要把页面做成批量编辑工作台。

## 11. 给 LLM 的输出约束

- 不要恢复批量 Plan 式编辑流程。
- 不要加入新的计划预览、审批或批量改名入口。
- 保持当前主线是“单曲编辑 + 异步回写 + Jobs 排障”。

## 12. 事实依据

- `/admin/library` 当前直接复用 `LibraryBrowser mode="admin"`。
- 管理模式提供 `edited` 过滤、`ignoreGlobal` 动作和 `TrackEditSheet`。
- 抽屉说明文案明确“这里不再走 Plan 式预览和审批流程”。
