# Music Tagger 管理台概览页 PRD

## 1. 文档定位

本文档描述 `/admin` 的当前真实形态。它是运维概览页，不是功能配置总入口，也不是全量任务管理中心。

## 2. 产品背景

当前系统已形成基础后台闭环：触发扫描、查看任务、浏览管理曲库、管理缓存和策略配置。管理台概览页负责把这些高频信息收束到一个入口页中。

## 3. 产品目标

- 快速判断系统是否健康。
- 让管理员一眼看到曲库规模、最近扫描、任务队列和缓存摘要。
- 提供到高频管理页面的快捷入口。

## 4. 用户与权限

- 目标用户：管理员。
- 权限边界：普通用户不应使用本页完成日常播放消费。
- 播放会话：页面展示 `admin` 临时试听摘要，不持久化为用户正式会话。

## 5. 页面定位

这是一个“运维 Dashboard”。

- 核心信息：曲库规模、扫描状态、任务队列、缓存概览、转码观测、最近曲目。
- 辅助信息：从这里跳去 `/admin/library`、`/admin/jobs`、`/admin/cache`、`/admin/settings`。

## 6. 页面结构

- 顶部状态区：系统空闲/扫描进行中、失败任务提醒、触发扫描按钮。
- 概览统计卡：曲目总数、专辑数、艺人数、任务队列状态。
- 中部双栏：
  - 最近扫描摘要
  - 快捷入口
- 下部双栏：
  - admin 当前试听摘要
  - 缓存概览
- 追加区块：转码观测、最近入库曲目列表。

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 曲库统计 | number | 曲目、专辑、艺人数 |
| 最近扫描任务 | object | 最近一次 `scan_full` 状态、进度、更新时间 |
| 任务队列摘要 | number | pending / running / failed 数量 |
| 缓存概览 | object | ready、pending、failed、stale、orphan 等摘要 |
| 转码策略 | object | 冷缓存天数、预算、单次上限 |
| 最近曲目 | array | 最近更新的管理区曲目摘要 |

## 8. 关键交互

1. 页面加载后并发拉取统计、任务、缓存、设置和最近曲目。
2. 管理员可直接触发一次 `scan_full`。
3. 有活动任务时，页面按轮询刷新关键区块。
4. 管理员可从概览页直接执行“清理失效缓存”“清理失败记录”。
5. 通过快捷入口跳转到对应管理页面继续排障或配置。

## 9. 页面状态

- 正常态：显示完整运维概览。
- 任务活跃态：顶部显示“扫描进行中”，关键区块自动刷新。
- 异常态：失败任务数量以 Badge 高亮。
- 加载失败：各查询通过 toast 提示加载失败。

## 10. 原型与 UI 设计指导

- 首屏应突出“健康度”和“下一步去哪排查”。
- 统计卡宜简洁，避免把它做成大而全的报表页。
- 最近扫描和缓存概览应是管理员最容易扫读的模块。
- admin 试听摘要保持工具化，不要产品化成完整播放器页。

## 11. 给 LLM 的输出约束

- 不要把本页扩写成完整任务表或完整缓存明细表。
- 不要加入普通用户区入口逻辑。
- 保持定位为“管理概览页”，不是二级页面的聚合替代品。

## 12. 事实依据

- 页面支持直接触发 `scan_full`。
- 当前已有从概览页进入音乐库、Jobs、缓存页、设置页的快捷入口。
- 页面展示的播放摘要绑定 `admin` 会话。
