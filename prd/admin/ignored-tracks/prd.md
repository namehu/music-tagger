# Music Tagger 全局忽略页 PRD

## 1. 文档定位

本文档描述 `/admin/ignored-tracks` 的当前页面边界。它用于管理对所有用户默认隐藏的曲目，不扩展为规则引擎。

## 2. 产品背景

当前系统已支持管理员在管理曲库中把曲目标记为“全局忽略”。全局忽略页用于集中回看、批量选择和解除这些记录。

## 3. 产品目标

- 让管理员看到哪些曲目被全局隐藏。
- 支持单条或批量解除全局忽略。
- 明确全局忽略对用户区和管理区默认曲库的影响。

## 4. 用户与权限

- 目标用户：管理员。
- 权限边界：普通用户不能设置或解除全局忽略。
- 当前限制：UI 不开放 `reason` 的录入和展示编辑。

## 5. 页面定位

这是一个“全局忽略清单页”。

- 页面强调回看和解除，不是从这里发起大量新增。
- 新增全局忽略主要发生在 `/admin/library`。

## 6. 页面结构

- 页面标题区：标题与影响范围说明。
- 主列表卡片：
  - 选择列
  - 标题、艺人、专辑、设置人、忽略时间、路径
  - 单条解除按钮
- 顶部批量动作区：批量解除已选曲目。

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| selectedTrackIds | string[] | 当前批量选择集合 |
| createdBy | object | 设置全局忽略的管理员 |
| createdAt | datetime | 全局忽略创建时间 |
| track path | string | 曲目路径摘要 |

## 8. 关键交互

1. 页面读取全局忽略列表。
2. 管理员可单选、多选或全选当前可见记录。
3. 点击“批量解除”后，对已选曲目批量移除全局忽略。
4. 也可在单条记录行内直接解除。
5. 列表变化后会自动清理已不可见的选择状态。

## 9. 页面状态

- 正常态：表格展示全局忽略记录。
- 空态：当前没有全局忽略曲目。
- 提交中：单条或批量解除按钮禁用。
- 失败态：toast 提示批量或单条解除失败。

## 10. 原型与 UI 设计指导

- 列表页应保持“可批量操作”的明显结构。
- 选择列和批量按钮需要在视觉上明确关联。
- 路径和设置人是辅助排障信息，不应压过曲目主信息。

## 11. 给 LLM 的输出约束

- 不要扩成目录规则、自动规则或扫描规则配置页。
- 不要在本页补充复杂筛选器或理由编辑器。
- 保持页面焦点是查看和解除全局忽略。

## 12. 事实依据

- 页面当前支持 `listGlobal`、`unignoreGlobal`、`batchUnignoreGlobal`。
- 选中状态会随着可见列表变化自动同步。
- 文案明确说明管理区和用户区默认曲库都会过滤这些曲目。
