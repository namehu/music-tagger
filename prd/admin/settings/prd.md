# Music Tagger 转码与缓存策略页 PRD

## 1. 文档定位

本文档描述 `/admin/settings` 的当前单文件 PRD。它聚焦转码与缓存策略配置，不扩展为通用系统设置中心。

## 2. 产品背景

系统已有缓存治理动作和容量裁剪能力，为了让管理员能直接调整阈值，需要一个稳定、轻量、可立即生效的后台配置页。

## 3. 产品目标

- 提供统一的缓存策略配置入口。
- 让管理员直接看到当前生效值。
- 让缓存页默认动作直接消费这里的配置。

## 4. 用户与权限

- 目标用户：管理员。
- 权限边界：普通用户不可访问。
- 当前范围：仅覆盖转码与缓存策略。

## 5. 页面定位

这是一个单页表单，而不是多分类设置中心。

- 上半部分负责回显当前生效策略。
- 下半部分负责修改并保存策略。

## 6. 页面结构

- 页面标题区：标题与作用说明。
- 当前生效策略卡片：冷缓存阈值、容量预算、单次清理上限、最后更新时间。
- 修改策略表单：
  - 冷缓存阈值（天）
  - 容量预算（GiB）
  - 单次清理上限
  - 保存按钮与校验提示

## 7. 页面字段定义

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 冷缓存阈值（天） | integer | 是 | `1..3650` |
| 容量预算（GiB） | integer | 是 | `0..1024` |
| 单次清理上限 | integer | 是 | `1..500` |
| 最后更新时间 | datetime | 否 | 用于展示最近一次保存时间 |

## 8. 关键交互

1. 页面加载当前转码策略并初始化表单。
2. 用户修改任意数字字段后，表单实时校验范围。
3. 点击“保存策略”后更新后台配置。
4. 保存成功后刷新设置与缓存相关查询，并提示成功。

## 9. 页面状态

- 加载中：读取当前生效值。
- 正常态：显示当前策略与可编辑表单。
- 非法输入态：保存按钮禁用，并显示错误提示。
- 保存中：按钮进入 pending 态。
- 失败态：toast 提示保存失败。

## 10. 原型与 UI 设计指导

- 保持单页、低复杂度的后台表单布局。
- 当前生效策略区与修改表单区要明显分层。
- 3 个核心策略值建议以指标卡 + 数字输入的组合表达。
- 辅助文案应强调“会直接影响 `/admin/cache` 默认动作”。

## 11. 给 LLM 的输出约束

- 不要扩成多 Tab 的系统设置中心。
- 不要加入审计历史、版本回滚或自动定时任务配置。
- 保持页面只管理冷缓存阈值、容量预算和单次清理上限。

## 12. 事实依据

- 页面当前调用 `settings.get` 和 `settings.updateTranscodePolicy`。
- 表单校验范围已固定在代码中。
- 保存成功后会同步刷新缓存相关查询。
