# Music Tagger 用户首页 PRD

## 1. 文档定位

本文档描述当前 `/dashboard` 的真实页面边界。它是已登录用户进入系统后的默认首页，强调“继续收听 + 最近使用”，不是完整的曲库操作页。

## 2. 产品背景

当前系统已具备用户曲库、歌单、忽略曲目和全局播放器。用户首页的职责是把最近播放、最近维护歌单、最近更新曲目与当前播放摘要聚合成一个继续入口。

## 3. 产品目标

- 让用户进入系统后快速继续上次的听歌上下文。
- 以最近使用为主，而不是重复建设完整曲库页面。
- 为用户区三个主入口提供快速跳转。

## 4. 用户与权限

- 目标用户：已登录普通用户与管理员的用户侧身份。
- 权限边界：本页属于用户区，不承担管理后台控制动作。
- 播放会话：绑定 `user` 正式播放会话，而不是管理试听会话。

## 5. 页面定位

这是一个“继续收听首页”。

- 核心内容：当前播放摘要、最近播放、最近歌单、最近更新曲目。
- 辅助内容：跳转到 `/library`、`/playlists`、`/ignored-tracks`。

## 6. 页面结构

- 顶部摘要：页面标题、最近播放数量、最近歌单数量。
- 统计卡区：曲目、专辑、艺人数。
- 主区左列：当前播放摘要卡、最近播放列表。
- 主区右列：快捷入口、最近更新歌单、最近更新曲目。

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| stats.tracks / albums / artists | number | 当前用户可见库统计 |
| recentPlays | array | 最近播放过的曲目摘要与播放时间 |
| recentPlaylists | array | 最近更新歌单名称、曲目数、更新时间 |
| recentTracks | array | 最近更新曲目的标题、艺人、专辑、更新时间 |
| 当前播放摘要 | object | 来自用户会话的当前曲目、恢复状态和跳转动作 |

## 8. 关键交互

1. 页面加载时请求 `library.dashboard`。
2. “最近播放”中的曲目可直接继续播放；若当前队列不是首页最近播放来源，会先重建队列再播。
3. “最近更新的歌单”点击后进入对应歌单详情。
4. “最近更新的曲目”只做信息展示，并提供前往 `/library` 的总入口。
5. 快捷入口直接跳到音乐库、歌单和我的忽略。

## 9. 页面状态

- 加载中：各卡片区域显示“正在加载”文案。
- 正常态：展示最近播放、最近歌单、最近曲目。
- 空态：
  - 无最近播放时提示先去音乐库点播
  - 无歌单时提示先创建歌单
  - 无最近曲目时提示先触发扫描

## 10. 原型与 UI 设计指导

- 首页应偏“继续使用”而不是“系统介绍”。
- 当前播放摘要应为首屏重点之一。
- 最近播放列表应保留显眼的继续播放动作。
- 最近歌单和最近曲目可采用较轻量的信息卡或按钮式列表。

## 11. 给 LLM 的输出约束

- 不要把本页扩写成完整曲库表格。
- 不要添加管理员运维卡片、扫描按钮或缓存治理动作。
- 保持页面定位为用户音乐区首页，而不是探索页或推荐页。

## 12. 事实依据

- 当前页面聚合 `library.dashboard` 数据，并复用 `CurrentPlaybackSummary`。
- 最近播放支持直接恢复到首页自己的最近播放队列。
- 首页当前公开的快捷入口只有 `/library`、`/playlists`、`/ignored-tracks`。
