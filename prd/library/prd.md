# Music Tagger 用户音乐库页 PRD

## 1. 文档定位

本文档描述 `/library` 的当前单页事实。页面复用 `LibraryBrowser` 的 `user` 模式，用于浏览、搜索、排序和点播曲库，不包含管理员单曲编辑能力。

## 2. 产品背景

当前系统已支持扫描曲库、全文搜索、原始播放和转码缓存播放。用户音乐库页是普通用户消费曲库的主入口。

## 3. 产品目标

- 提供用户区的主曲库浏览入口。
- 支持搜索、排序、点播和加入“我的忽略”。
- 与底部全局播放器共享同一用户播放队列。

## 4. 用户与权限

- 目标用户：已登录用户。
- 权限边界：用户可播放和忽略曲目，但不能打开管理员编辑抽屉。
- 默认过滤：用户区曲库默认过滤“全局忽略 + 我的忽略”。

## 5. 页面定位

这是用户侧标准曲库列表页。

- 核心任务：找歌、播歌、继续当前队列。
- 辅助任务：把不想看的曲目加入“我的忽略”。

## 6. 页面结构

- 页面标题区：标题与简短说明。
- 统计卡区：曲目、专辑、艺人数。
- 列表控制区：搜索框、排序按钮、当前队列状态提示。
- 曲目表格：播放按钮、操作按钮、标题、艺人、专辑、路径、更新时间。

## 7. 页面字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 搜索词 | string | 按标题、艺人、专辑、文件名或路径搜索 |
| 排序 | enum | `recent / title / artist` |
| 统计卡 | number | 当前可见曲库统计 |
| 队列来源标记 | string | 当前播放队列是否来自本列表 |
| 曲目行 | array | 曲目基础信息与播放状态 |

## 8. 关键交互

1. 页面加载时读取用户曲库统计和曲目列表。
2. 用户输入搜索词后，以延迟值触发搜索。
3. 点击排序按钮切换结果排序方式。
4. 播放某首曲目时，如当前队列不是本页来源，会先把可见列表设为用户队列，再开始播放。
5. 用户可对某首歌执行“加入我的忽略”。

## 9. 页面状态

- 加载中：统计和列表显示加载文案。
- 搜索中：顶部显示“搜索中…”提示。
- 正常态：显示曲目表格与当前播放状态。
- 空态：无结果时显示空列表提示。
- 播放准备态：对应曲目显示“准备中”。

## 10. 原型与 UI 设计指导

- 保持“列表优先”的内容密度。
- 顶部筛选和排序应明显但不过度抢占首屏。
- 播放状态和当前队列来源要可感知，便于理解“为什么这首歌会接着切”。
- “加入我的忽略”应是次级操作。

## 11. 给 LLM 的输出约束

- 不要加入管理员编辑面板、批量操作或计划执行入口。
- 不要提供“显示已忽略曲目”的切换器。
- 保持单页职责聚焦在浏览、搜索、播放和个人忽略。

## 12. 事实依据

- `/library` 直接渲染 `LibraryBrowser mode="user"`。
- 用户模式会把当前列表设为 `user` 播放队列来源。
- 页面允许执行 `ignoreMine`，不暴露 `ignoreGlobal` 或 `TrackEditSheet`。
